Use the shared components before building your own. They give users the same data and behaviour across services, and save each team from solving the same problem.

Shared components

DfE Core solution

The DfE Core solution (DfECoreSolution) holds the components every DfE CRM should share. It uses the dfe_ publisher prefix. It includes:

  • DfE's extensions to the Account and Contact tables
  • reference tables for school and establishment data from GIAS, such as local authorities, government regions and phases of education
  • DfE-wide choices, such as the DfE yes/no choice (dfe_dfeyesnooptionset)
  • a standard set of table icons

Install it in your environment rather than creating your own versions of these components. Don't change its components in your own solutions. If something is missing that other services would also need, ask the Solutions Delivery Team to add it to the core solution.

GIAS data

School and establishment data comes from Get Information about Schools (GIAS) (opens in a new tab) through a shared integration that is being rolled out across DfE CRMs. Don't build your own GIAS import.

  • GIAS files are downloaded every day and loaded into a central Dataverse environment with Azure Data Factory.
  • Each CRM that subscribes receives the GIAS tables and columns it has chosen, in the DfE Core tables in its own environment.
  • Subscriptions are managed centrally. Contact the Solutions Delivery Team to subscribe or to change the data your service receives.

Building something reusable

If you build something other services could use:

  • make it generic and configurable, with no service-specific logic or hard-coded values
  • put it in the core solution for its CRM, or in the DfE Core solution if it applies across DfE, following the publisher prefix rules
  • give it a named owner and document how to use it
