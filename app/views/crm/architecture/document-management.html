The standard

Store documents for Dynamics 365 records in SharePoint Online, using the out-of-the-box SharePoint integration. Don't store large numbers of files in Dataverse: its file storage is limited and charged for, and SharePoint gives versioning, co-authoring and retention that Dataverse does not.

Microsoft explains how to set up the SharePoint integration (opens in a new tab).

Configuration

  • Use SharePoint Online, not on-premises SharePoint.
  • Use one parent SharePoint site for each environment, unless there is a strong business reason not to.
  • Use the default folder for each record, and let Dynamics 365 create the folders.
  • Keep the folder structure shallow.
  • Only add SharePoint metadata where there is a reporting or governance need.
  • Rely on versioning rather than saving copies of files.

Security

Dynamics 365 security roles are not copied to SharePoint, so design SharePoint access as part of the service.

  • Control access at site or library level, with Microsoft Entra security groups that match your user roles.
  • Only give site access to users who are allowed to see the documents in Dynamics 365.
  • Only set permissions on individual folders for a small number of records with a genuine confidentiality need. Automate it, and document it for support teams.
  • Keep highly sensitive documents in a separate SharePoint site with sensitivity labels, retention policies and Conditional Access. Link to them from Dynamics 365 rather than storing them against standard records.

What to avoid

  • Custom document storage solutions
  • Custom code to copy Dynamics 365 security to SharePoint
  • Breaking permission inheritance on large numbers of folders
  • Storing emails or system-generated files without a business need
