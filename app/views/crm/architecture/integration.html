Choose an integration pattern based on how quickly the other system needs the data and how much data moves, then choose the simplest technology that supports it.

Choose the pattern

When to use each integration pattern
Pattern Use it when Example
Synchronous request (API) A user needs the result straight away. Only use it for genuinely real-time needs, because the calling system depends on Dataverse being available and responsive. Creating a case and showing the user its reference number
Asynchronous messaging The work can happen in the background, or volumes are high. Design for retries, message order and processing the same message twice. Sending case updates to another system without slowing the user down
Publish and subscribe Several systems need to react to the same change. Subscribers handle their own retries. A grant approval updating finance and reporting systems
Batch Large volumes move on a schedule and a delay is acceptable. The daily load of school and establishment data from GIAS
File-based Only when the other system has no API. Avoid it otherwise, because errors are found late and the data arrives late. Exchanging files with a partner over SFTP

Choose the technology

  • Power Automate for low-volume, event-driven integration with services that have a connector. Use a custom connector to call an API that has no connector. Don't use it for high volumes, complex transformation or anything that needs guaranteed delivery.
  • Power Pages server logic for a website that needs to call another service or use a secret. See server logic.
  • Azure Functions for custom processing, validation or transformation in code.
  • Azure API Management in front of APIs that other systems call, to control access and apply policies.
  • Azure Service Bus for reliable asynchronous messaging between systems.
  • Azure Event Grid to send events to several subscribers.
  • Azure Logic Apps to orchestrate long-running integrations across several systems.
  • Azure Data Factory for batch loads of large data sets, such as the shared GIAS data.

Microsoft's documentation explains each one: Azure Functions (opens in a new tab), Service Bus (opens in a new tab), Event Grid (opens in a new tab), Logic Apps (opens in a new tab) and Data Factory (opens in a new tab).

Standards for every integration

  • Use shared integrations, such as GIAS, rather than building your own.
  • Log failures where support teams can see them, and make it possible to process failed messages again.
  • Don't let other systems depend on the Dataverse data model. Give them a stable API or message format.
