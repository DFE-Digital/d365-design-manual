Microsoft explains how solutions work (opens in a new tab). Every DfE CRM follows the standards on this page, and the standard pipelines rely on them.

Unmanaged and managed solutions

  • Make every change in an unmanaged solution in Dev. Dev is the only environment with unmanaged solutions.
  • Keep the unmanaged solutions in source control, so Dev can be rebuilt.
  • Deploy to Test, PreProd and Prod only as managed solutions exported from Dev, through the pipelines.
  • Never make unmanaged changes, or edit components directly, in Test, PreProd or Prod.

Standard solution model

Use these solution names exactly, because the pipelines depend on them.

A CRM with one service

  • [Service name] Configuration
  • [Service name] Customisation
  • [Service name] Portal, if the service has a Power Pages site

For example, a CRM that only hosts the ICA service has ICA Configuration, ICA Customisation and ICA Portal.

A CRM with several services

Add a core solution for the CRM, then the same three solutions for each service:

  • [CRM name] Core
  • [Service name] Configuration
  • [Service name] Customisation
  • [Service name] Portal, if the service has a Power Pages site

For example, the APM CRM has APM Core, and the Breakfast Club service has Breakfast Club Configuration, Customisation and Portal. The core solution and each service use their own publisher and prefix, such as apm_ and bc_. See publisher prefixes.

The core solution holds the components every service in the CRM shares, such as core apps, shared tables like Contact and Case, global choices, shared security roles and reusable web resources. Never duplicate these or change them differently for one service. If a service needs something extra, such as a new column on Contact, add it in that service's solution.

The core solution is installed first and each service's solutions are layered on top. To avoid conflicts between unmanaged solutions, consider developing the core solution in its own Dev environment, and installing it as a managed solution in the services' Dev environment.

What goes in each solution

Components in each solution
Solution Components
Configuration Apps, sitemaps, tables, choices, dashboards, email templates, security roles and web resources
Customisation Power Automate flows, plugins, real-time classic workflows, environment variables and connection references
Portal The Power Pages site, site components, site languages and environment variables

If you're not sure where something belongs, ask the Solutions Delivery Team at solutionsdevelopment.techdirectorate@education.gov.uk.
