The standard

  • Keep all solution source, Power Pages configuration, reference data and deployment scripts in Azure DevOps repositories.
  • Deploy everything through Azure DevOps pipelines: Dynamics 365 solutions, Power Pages sites, and the reference and configuration data they need.
  • Never import solutions by hand into Test, PreProd or Prod, or change those environments directly.
  • Parameterise pipelines so the same pipeline deploys to every environment.
  • Keep production deployments controlled and auditable.

Use the standard pipelines

The Solutions Delivery Team provides standard Azure DevOps pipelines. Use them wherever possible, rather than building your own. They:

  • export your solutions and reference data from Dev into source control
  • build the release from source control
  • deploy managed solutions, Power Pages sites and reference data through Test, PreProd and Prod
  • generate release notes

They depend on the standard solution model and its solution names. Templates and instructions are on the Solutions Development Azure DevOps wiki. Check it before you create or change a pipeline.

Microsoft explains the Power Platform Build Tools for Azure DevOps (opens in a new tab) that the pipelines use.
