Environment model

Every DfE CRM uses the same four environments, so teams can move between services without learning a new set-up.

Rules for each environment

Rules for each environment
Environment Used for Rules
Dev All configuration and development The only environment with unmanaged solutions. Developers only. Sample test data only.
Test Functional and integration testing, and checking fixes Managed solutions only. Owned by the testers. Developers only use it to investigate defects.
PreProd User and operational acceptance testing, regression testing and release rehearsals Managed solutions only. As close to Prod as possible, and controlled like Prod: every change needs a formal change request.
Prod The live service Managed solutions only, released through the formal release process. Admin access for a small number of named people. Developers have standard user accounts at most. Don't sign in as the service account, and restrict access to its credentials.

Keeping environments consistent

Keep system settings, solutions, security and integrations the same across all four environments, so deployments behave the same way everywhere. Deploy to Test, PreProd and Prod only through the Azure DevOps pipelines.

Requesting a new environment

Environments are created in the Power Platform admin center by administrators with the Dynamics 365 Administrator role in Microsoft Entra ID. To keep environments consistent and secure, only the Solutions Delivery Team creates them.

To request a new environment, including a temporary sandbox for project work, email the Solutions Delivery Team at solutionsdevelopment.techdirectorate@education.gov.uk.
