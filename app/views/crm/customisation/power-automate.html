When to use Power Automate

Use Power Automate for simple automation and integration that can run in the background, such as:

  • sending notifications when records change
  • creating or updating related records with straightforward logic
  • moving small amounts of data between systems
  • calling an API through a connector when a short delay doesn't matter

Use a plugin instead if the logic is complex, must perform well at volume, or must run before the record is saved, such as validation.

Microsoft's guidance on using Power Automate with Dataverse (opens in a new tab) explains triggers and actions.

How to build flows

  • Build flows only in Dev, inside your service's Customisation solution, and deploy them with the solution through the Azure DevOps pipelines.
  • Keep each flow small, with one clear purpose. Split complex logic into child flows.
  • Don't rebuild in a flow something configuration already does.
  • Use trigger conditions to avoid unnecessary runs, and filter rows when you list records, to keep API calls down.
  • Add error handling, and log failures where support teams will see them, such as a Dataverse table, Application Insights or an alert email.
  • Name flows consistently, and add a description of what each one does and what triggers it.

Connections

  • Use connection references, and include them in the solution.
  • Connect with a service account or application user. Flows must never be owned by, or connect as, a person.

Licensing

DfE's Dynamics 365 licences cover flows that use Dynamics 365 data. A flow that doesn't connect to Dynamics 365 may need extra licences. See licensing.
