Use business rules first

Use a business rule for simple logic, such as showing, hiding, locking or setting fields, and validating with simple conditions. Business rules need no code, are visible on the table, and work in the web and mobile apps.

A rule scoped to a form only runs in the browser. A rule scoped to Entity also runs on the server, so it applies when records are saved through imports, flows or the API. Use Entity scope for any rule that must always apply.

Microsoft explains how to create business rules (opens in a new tab).

Use JavaScript when business rules aren't enough

Use JavaScript for logic that business rules can't handle well, such as complex branching, controlling tabs and sections, or calling an API from the form.

Also use it when a business rule would become too complex. Large or overlapping rules slow the form down and are hard to debug, and a small, well-written script is often faster and easier to maintain.

Standards

  • Use the simplest option that meets the requirement.
  • Don't rely on JavaScript, or business rules scoped to a form, for validation that must always apply. Users can get around anything that only runs in the browser. Use a business rule scoped to Entity or a plugin instead.
  • Keep JavaScript in source control, and review and test it like any other code.
