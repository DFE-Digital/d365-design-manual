Meet every requirement with the simplest option that works, in this order. Only move to the next option when the one before it can't meet the need.

Order of preference for changes
Order Option Examples
1 Configuration Tables, columns, forms, views, apps, dashboards, email templates, security roles, teams, business units, queues, SLAs, routing rules and duplicate detection
2 Low-code Business rules, formula columns, Power Automate flows, and Power Fx in command bar buttons and canvas apps
3 Pro-code Plugins, form scripts in JavaScript, PCF controls, and Azure Functions or Logic Apps for integration

Why this order

Each step adds more to build, test, deploy and support. Configuration stays closest to Microsoft's product, so it's the easiest to upgrade. Low-code still needs managing through the same release process, and too much of it scatters logic and slows the platform. Pro-code needs specialist skills, code review and testing, and adds dependencies outside the platform.

When pro-code is the better choice

Use a plugin for simple logic when it's clearly more reliable or efficient than the low-code option, for example when the logic must run synchronously, must run for imports and API calls, or must perform well at volume. Record why you chose it.
