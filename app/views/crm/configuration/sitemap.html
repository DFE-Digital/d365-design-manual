Microsoft explains how to build a sitemap with areas, groups and subareas (opens in a new tab). Follow these standards when you do.

Group tables by capability

  • Group tables by what users do with them, such as Contacts, Cases or Applications.
  • Keep group names short and meaningful.
  • Keep each group to 5 to 7 items, and only add groups when you need them.

Keep configuration tables apart

Don't put reference, settings or admin-only tables alongside business data. Either:

  • add a Configuration group in an admin area, or
  • if there are a lot of them, put them in a separate configuration app for administrators and support teams

Name items clearly

  • Use 1 or 2 words in plain English, in the words users use every day.
  • Don't use prefixes, abbreviations or project names.

Use consistent icons

Give every custom table in the sitemap a custom icon that matches Microsoft's own icons:

  • SVG format, 32 by 32 pixels
  • a single colour, black or dark grey
  • a simple line style, not filled or multi-coloured
  • simple enough to read at a small size

Check the icons in the DfE Core solution before creating your own.

Use security roles to hide items

Users only see sitemap items for tables they have permission to read. Use security roles to hide admin areas, rather than creating extra apps, and test with real user accounts.
