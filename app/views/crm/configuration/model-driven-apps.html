Use Microsoft's apps first

Use a Dynamics 365 app, such as the Copilot Service workspace or Dynamics 365 Contact Center, when the service fits a standard capability such as case management, multi-session working or contact centre work. These apps get Microsoft's new features automatically, and a custom app can't provide multi-session working.

When to build a custom app

Build a custom model-driven app when users need a simpler, single-session app focused on their tasks. You then take on keeping it up to date with platform changes.

Standards

  • Build apps around a business capability, not a team. Teams that work with the same tables and processes use the same app.
  • Don't copy an app to give a team its own name or branding. Use security roles, views and dashboards to tailor the shared app.
  • Check whether an existing app already covers the tables your service uses before building a new one.
  • Keep the number of apps in an environment low, because each one adds maintenance and training.
  • Design navigation around how users work, not how the data is structured. See sitemaps.

Microsoft's overview of model-driven apps (opens in a new tab) explains how they work.
