Server logic lets you write JavaScript that runs on the Power Pages server rather than in the user's browser. The browser calls it through the Power Pages Web API, at /_api/serverlogics/<name>, and gets back whatever the script returns.

When to use server logic

Use server logic when the work can't or shouldn't happen in the browser, for example to:

  • call an external API that needs a key or secret, such as the DfE virus scanning service
  • check data the user shouldn't be able to see or change, such as a record's status, before acting on it
  • run checks that users mustn't be able to skip by changing the page's JavaScript
  • combine several Dataverse calls into one request from the browser

For simple reads and writes to records the user has permission to change, use the CRM helper framework and the Power Pages Web API instead. Table permissions still apply to server logic, so it doesn't give users access to data they couldn't otherwise reach.

Before you start

Server logic is newer than the rest of Power Pages, and Microsoft's documentation misses some important behaviour. Read behaviour and limitations before you write your first script. It covers JavaScript that crashes the script, size and memory limits, and how to debug the generic "Exception occurred while processing this request" error.

Microsoft's guidance is in Power Pages server logic overview (opens in a new tab).
