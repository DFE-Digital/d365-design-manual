Scan every file users upload before you save it to CRM. The CRM helper framework does this for you when it validates a file input, as long as your site has the VirusScan server logic.

How it works

  1. The user selects a file and submits the page.
  2. DfEPortal.ValidateData checks the file's type, number and size, then sends it to the VirusScan server logic.
  3. The server logic passes the file to the DfE virus scanning service and returns the result.
  4. If any file isn't clean, the framework shows an error and the page stops.
  5. If every file is clean, your page saves the record and uploads the file.

The scanning service's address and key stay on the server, so they're never sent to the browser.

Before you start

You need:

  • version 03 or later of the framework, for files larger than about 750 KB (see framework versions)
  • the address and key of the DfE virus scanning service for each of your environments
To get access to the virus scanning service, email Eddie Haynes or Steve Tam in the Solutions Delivery Team. Tell them your service's name and which environments you need.

Check whether your site already has it

Sites created from the website import tool include the VirusScan server logic. To check, open your site in Power Pages design studio, go to Set up, then Server logic, and look for VirusScan.

If it's there, check it against the steps on this page, in particular the site settings and updating an older VirusScan. If it isn't, for example because your site was built before it was added, set it up yourself.

Set up the VirusScan server logic

If you haven't used server logic before, read setting up server logic first.

Site settings

Name Value
ServerLogic/Enabled true
ServerLogic/MaxMemoryUsageInBytes 41943040

Without the memory setting, files over about 2 MB fail with "An error occurred. Please try again.". Type its name exactly: Power Pages ignores other spellings without telling you.

Environment variables

Create 2 environment variables in your solution, using your publisher prefix in place of dfe_:

  • dfe_virusscanurl: the virus scanning service's address
  • dfe_virusscankey: its key, as a secret environment variable backed by Azure Key Vault

Set a value for each environment. Don't type the address or key into the server logic code: code is exported with your site, so it would end up in solution files and source control.

Server logic record

  • Name: VirusScan, exactly. The framework calls /_api/serverlogics/VirusScan.
  • Description: Sends uploaded files to the DfE virus scanning service and returns whether each one is clean.
  • Web roles: every web role whose users upload files.
  • Table permissions: none. The script doesn't read or write Dataverse.

Server logic code

const VIRUS_SCAN_URL = Server.EnvironmentVariable.get("dfe_virusscanurl");
const VIRUS_SCAN_KEY = Server.EnvironmentVariable.get("dfe_virusscankey");

async function post() {
  try {
    // Forwarded as it is, without parsing, to keep memory use down for large files.
    // The scanning service checks the body.
    const raw = Server.Context.Body || "";

    if (raw.indexOf('"files"') === -1) {
      throw new Error("Missing files array");
    }

    const response = await Server.Connector.HttpClient.PostAsync(
      VIRUS_SCAN_URL,
      raw,
      { "x-functions-key": VIRUS_SCAN_KEY },
      "application/json"
    );

    const parsed = typeof response === "string" ? JSON.parse(response) : response;

    if (!parsed.IsSuccessStatusCode) {
      throw new Error("Virus scan service returned " + parsed.StatusCode + ": " + (parsed.ServerErrorMessage || parsed.Body));
    }

    const inner = typeof parsed.Body === "string" ? JSON.parse(parsed.Body) : parsed.Body;

    return JSON.stringify({
      status: "success",
      results: inner.results
    });

  } catch (err) {
    Server.Logger.Error("VirusScan failed: " + err.message);
    return JSON.stringify({
      status: "error",
      message: err.message
    });
  }
}

The script doesn't parse the files or log them. Holding a large file in memory more than once can stop the script with the platform's generic error, which your catch can't handle. See the memory limit.

Scan files on your page

Add a file input to your web template, using either the plain GOV.UK file input or the improved file upload component. Both work with the framework from version 03. See the file upload component for the HTML.

Include the file input in your validation data object. The framework scans the file when you call ValidateData.

const inputs = [
  {
    identifier: "dfe_evidencefile",
    type: "file",
    friendlyName: "your evidence",
    required: true,
    allowedFileTypes: ["pdf", "docx", "csv"],
    maxFileSize: 3,
    fileLimit: 1
  }
];

$("#submit-btn").on("click", async function (e) {
  e.preventDefault();
  DfEPortal.DisableButton("submit-btn");
  DfEPortal.ShowLoadingSpinner("loading-spinner");

  try {
    // Checks the type, number and size of files, then scans them
    const isValid = await DfEPortal.ValidateData(inputs);
    if (!isValid) {
      return;
    }

    // Save the record first, then upload the file to it
    await DfEPortal.WebApi.Update(recordId, "dfe_applications", dataObj);
    await DfEPortal.WebApi.UploadFile("dfe_evidencefile", "dfe_applications", recordId);
  } finally {
    DfEPortal.HideLoadingSpinner("loading-spinner");
    DfEPortal.EnableButton("submit-btn");
  }
});
  • Write allowedFileTypes in lowercase, without the dot.
  • maxFileSize is in megabytes. Keep it within the sizes in file sizes.
  • If the file input is optional and the user hasn't selected a file, the framework skips the checks and the scan. Only call UploadFile when a file was selected.

What users see

When Error message
The scanning service finds a virus, or can't scan the file Virus detected in file '[file name]'
The server logic or the scanning service fails An error occurred. Please try again.

A file the scanning service can't scan is treated as unsafe, so users see "Virus detected" for it too. The service's own error is in the response, in each result's error property, if you need to tell the two apart.

File sizes

Files are sent to the server logic as base64, which is about a third bigger than the file. Every file the user selects for one input is sent in the same request.

Set-up Largest file that works
Framework version 02 or earlier About 750 KB
Version 03, without the memory setting About 2 MB
Version 03, with ServerLogic/MaxMemoryUsageInBytes set to 40 MB At least 3.5 MB (the largest we've tested)

Test the largest file your service expects in each environment before you go live.

Updating an older VirusScan

Older versions of the VirusScan server logic parse the request and build it again before sending it on. They work for small files, but can run out of memory with large ones. Replace the code with the current version if yours:

  • calls JSON.parse(Server.Context.Body) and then JSON.stringify before PostAsync
  • has the scanning service's address or key typed into the code
  • parses parsed.Body before checking IsSuccessStatusCode

If a key has been typed into the code, ask for a new one when you move it to an environment variable, because the old one will be in your solution files and source control.

Request and response

You only need this if you're writing your own client or server logic.

Request from the browser

POST /_api/serverlogics/VirusScan, sent as text/plain; charset=utf-8, with a JSON body:

{
  "files": [
    {
      "fileName": "evidence.pdf",
      "mimeType": "application/pdf",
      "fileContent": "JVBERi0xLjcKJ..."
    }
  ]
}

fileContent is the file as base64, without a data: prefix.

Response from the server logic

// Scanned
{
  "status": "success",
  "results": [
    { "fileName": "evidence.pdf", "clean": true, "error": null }
  ]
}

// The server logic or the scanning service failed
{
  "status": "error",
  "message": "Virus scan service returned 401: ..."
}

This is returned inside the data property of the server logic envelope. The framework treats any result with clean: false as a virus, and any status other than success as an error.
