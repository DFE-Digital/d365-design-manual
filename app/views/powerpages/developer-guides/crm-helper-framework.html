The CRM Helper Framework is a JavaScript library designed to simplify validation and data submission tasks in Power Pages, particularly for interacting with Dynamics 365. It provides a set of reusable functions to handle form validation, data submission to CRM entities, and user experience enhancements like error handling, button state management, and loading spinners. This framework is pre-installed with the base portal, making it readily available for you to use in your front-end development.

This page describes version 03 of the framework. To find out which version your site uses and what's changed, see framework versions.

Some work can't be done safely in the browser, such as virus scanning files or calling a service that needs a key. For that, use server logic.

Before you start

The base portal sets up everything the framework needs. If you're using your own layouts, make sure every page has:

  • jQuery, loaded before the framework
  • GOV.UK Frontend, started with initAll()
  • a call to DfEPortal.WebApi.Init(), which sets up webapi.safeAjax with the site's anti-forgery token. The base portal's footer template does this.
  • an empty <div id="error-summary-container"></div> where the error summary should appear. The base portal's layouts include it.

Your HTML also needs to follow these conventions, which the component pages' examples already do:

  • each field is inside a govuk-form-group
  • a field's id is its column's logical name, which you also use as its identifier
  • radios and checkboxes share a name equal to the identifier
  • a date input's day, month and year fields share a name equal to the identifier, and their ids contain -day, -month and -year
  • the main submit button has the id submit-btn, because the framework's general error links to it

Creating your validation data object

Before using the framework's validation functions, you must create a validation data object. This object is an array of input objects, where each object describes a form field to validate. You can define a single input as [{...}] or multiple inputs as [{...},{...},{...}].

Base properties for all input types
Key Type Description
identifier String The schema name of the target CRM field (e.g., dfe_firstname).
type String The type of input displayed on the page. Supported types: text, text-area, email, tel, number, whole-number, decimal-number, money, date, radio, checkbox, select, file
friendlyName String A user-friendly name for the input, used in error messages.
e.g. "your first name" will display as "Enter your first name".
required Boolean true if the field must be answered. If it's false and the field is empty, the framework skips its other checks. If the user has entered something, it's still checked.
description String (optional) Text added to the end of a length or value limit error, for example to explain the limit. Leave it out unless you need it.

Some input types use more properties, such as targetType for radios, checkboxes and selects, and the file properties for file inputs. They're shown in the examples by input type.

Limits set in the HTML

Set length and value limits as attributes on the input itself, not in the validation data object.

Attribute Where What it checks
minchar, maxchar Text, textarea, email and whole number inputs The number of characters
minvalue, maxvalue Number inputs The value. The limits are read as whole numbers.
data-maxlength The govuk-character-count container around a textarea The number of characters
data-maxwords The govuk-character-count container around a textarea The number of words

The framework doesn't check mindate or maxdate in version 03. If a date must be in a range, check it in your own code.

InputObj examples by input type

Expand the sections below to see complete inputObj examples, when to use each configuration, and what the ConstructData function outputs.

Text input

Standard text input

Use for single-line text fields like names, references, or short answers.

{
  identifier: "dfe_firstname",
  type: "text",
  friendlyName: "your first name",
  required: true
}

ConstructData output:

{ "dfe_firstname": "John" }

Text input for record search (lookup)

Use when you need to search for a record by a text value (e.g. finding an application by reference number). The framework validates that the record exists and stores the record ID for submission.

{
  identifier: "dfe_applicationref",
  type: "text",
  friendlyName: "application reference",
  required: true,
  targetType: "lookup",
  targetEntity: "dfe_applications",
  targetEntityPrimaryKey: "dfe_applicationid",
  targetEntitySearchField: "dfe_referencenumber"
}

ConstructData output (creates an OData bind to the found record):

{ "dfe_applicationref@odata.bind": "/dfe_applications(abc123-def456-...)" }

ValidateData searches targetEntity for a record whose targetEntitySearchField matches the value, and saves its ID on the input object as targetEntityId. If nothing matches, the user sees "[friendlyName] cannot be found". Always call ValidateData before ConstructData for lookups: without a targetEntityId, ConstructData sets the column to null.

Textarea

Use for multi-line text fields. Supports character count and word count validation when used with the GOV.UK character count component.

{
  identifier: "dfe_description",
  type: "text-area",
  friendlyName: "a description",
  required: true
}

ConstructData output:

{ "dfe_description": "This is the user's multi-line input..." }

If using with character count, add data-maxlength (characters) or data-maxwords (words) to the .govuk-character-count container element.

  • Characters: every character counts, including spaces and line breaks.
  • Words: anything separated by spaces or line breaks counts as a word. Blank lines and paragraph breaks don't count as words.
! Warning For a word limit, use data-maxwords, not GOV.UK Frontend 6.6's data-maxlength with data-count-type="words". The framework doesn't support the newer markup yet: it would treat the limit as characters and wouldn't check the number of words.

Email input

Use for email address fields. Validates email format automatically.

{
  identifier: "emailaddress1",
  type: "email",
  friendlyName: "your email address",
  required: true
}

ConstructData output:

{ "emailaddress1": "user@example.com" }

Telephone input

Use for UK telephone numbers. Validates UK phone number formats including mobile, landline, and international (+44) formats.

{
  identifier: "telephone1",
  type: "tel",
  friendlyName: "your telephone number",
  required: true
}

ConstructData output:

{ "telephone1": "07700 900 982" }

Number inputs

Whole number

Use for integer values. Validates that the input is a whole number without decimals.

{
  identifier: "dfe_quantity",
  type: "whole-number",
  friendlyName: "quantity",
  required: true
}

ConstructData output:

{ "dfe_quantity": 5 }

Decimal number

Use for values that require decimal places.

{
  identifier: "dfe_percentage",
  type: "decimal-number",
  friendlyName: "percentage",
  required: true
}

ConstructData output:

{ "dfe_percentage": 75.5 }

Money

Use for currency values. Similar to decimal-number but formats error messages with currency symbols.

{
  identifier: "dfe_amount",
  type: "money",
  friendlyName: "amount",
  required: true
}

ConstructData output:

{ "dfe_amount": 1500.00 }

Number (general)

Use when you need basic number validation without whole/decimal restrictions.

{
  identifier: "dfe_value",
  type: "number",
  friendlyName: "value",
  required: true
}

You can add minvalue and maxvalue attributes to the HTML input element to limit the value, and minchar and maxchar to limit the number of characters of a whole number. See limits set in the HTML.

  • ConstructData only converts the value to a number if the input has inputmode="numeric". Otherwise it sends the value as text.
  • decimal-number expects a decimal point: "75" fails with "[friendlyName] must be a decimal number". Use money or number if whole amounts are allowed.
  • number is only checked when required is true.

Date input

Date to date/time field (default)

Use when submitting to a CRM date/time field. Outputs ISO format.

{
  identifier: "dfe_dateofbirth",
  type: "date",
  friendlyName: "your date of birth",
  required: true
}

ConstructData output:

{ "dfe_dateofbirth": "1990-05-15" }

Date to text field

Use when submitting to a CRM text field instead of a date/time field. Outputs DD/MM/YYYY format.

{
  identifier: "dfe_datetext",
  type: "date",
  friendlyName: "the date",
  required: true,
  targetType: "text"
}

ConstructData output:

{ "dfe_datetext": "15/05/1990" }

If none of the date fields are filled in, ConstructData sends null. The framework checks that the date is complete and real, including leap years, but doesn't check mindate or maxdate in version 03.

Radio inputs

Radio to boolean field

Use for Yes/No questions that map to a CRM Yes/No (boolean) field. Radio values should be 1 for Yes and 0 for No.

{
  identifier: "dfe_agreeterms",
  type: "radio",
  friendlyName: "if you agree to the terms",
  required: true,
  targetType: "bool"
}

HTML:

<input type="radio" name="dfe_agreeterms" value="1"> Yes
<input type="radio" name="dfe_agreeterms" value="0"> No

ConstructData output:

{ "dfe_agreeterms": true }

If no option is selected, ConstructData sends false. On a page the user can save before answering, such as with "Save and return", leave unanswered Yes/No questions out of the inputs you pass to ConstructData, or they'll be saved as No.

Radio to choice column (option set)

Use when mapping to a CRM choice column. Radio values should be the option set integer values.

{
  identifier: "dfe_contactpreference",
  type: "radio",
  friendlyName: "your contact preference",
  required: true,
  targetType: "select"
}

HTML:

<input type="radio" name="dfe_contactpreference" value="100000000"> Email
<input type="radio" name="dfe_contactpreference" value="100000001"> Phone
<input type="radio" name="dfe_contactpreference" value="100000002"> Post

ConstructData output:

{ "dfe_contactpreference": 100000001 }

Radio to lookup field

Use when each radio option represents a different record in a related table. Radio values should be the GUIDs of the related records.

{
  identifier: "dfe_region",
  type: "radio",
  friendlyName: "your region",
  required: true,
  targetType: "lookup",
  targetEntity: "dfe_regions"
}

HTML:

<input type="radio" name="dfe_region" value="abc123-..."> North
<input type="radio" name="dfe_region" value="def456-..."> South

ConstructData output:

{ "dfe_region@odata.bind": "/dfe_regions(abc123-...)" }

Radio to text field

Use when you want to store the label text of the selected option rather than a value.

{
  identifier: "dfe_selectedoption",
  type: "radio",
  friendlyName: "an option",
  required: true,
  targetType: "text"
}

ConstructData output (stores the label text):

{ "dfe_selectedoption": "Option A" }

Radio to split fields

Use when different radio selections should write to different CRM fields. The id attribute of each radio becomes the field name.

{
  identifier: "contact-method",
  type: "radio",
  friendlyName: "how to contact you",
  required: true,
  targetType: "split-field",
  targetFieldType: "text"
}

HTML:

<input type="radio" name="contact-method" id="dfe_emailaddress" value="user@example.com"> Email
<input type="radio" name="contact-method" id="dfe_telephone" value="07700900123"> Phone

ConstructData output (if Email selected):

{ "dfe_emailaddress": "user@example.com" }

ConstructData output (if Phone selected):

{ "dfe_telephone": "07700900123" }

Checkbox inputs

Checkbox to boolean field

Use for a single checkbox that maps to a Yes/No field. Checkbox value should be 1.

  type: "checkbox",
  friendlyName: "if you consent to marketing",
  required: true,
  targetType: "bool"

ConstructData output:

Checkbox to choice column (single selection)

Use for a single checkbox that sets a choice column value.

{
  identifier: "dfe_status",
  type: "checkbox",
  friendlyName: "the status",
  required: true,
  targetType: "select"
}

ConstructData output:

{ "dfe_status": 100000001 }

Checkbox to multi-select choice column

Use for multiple checkboxes that map to a multi-select choice column (choices). Values are submitted as a comma-separated string.

{
  identifier: "dfe_interests",
  type: "checkbox",
  friendlyName: "your interests",
  required: true,

HTML:

<input type="checkbox" name="dfe_interests" value="100000001"> Music
<input type="checkbox" name="dfe_interests" value="100000002"> Travel

ConstructData output (multiple selected):

{ "dfe_interests": "100000000,100000001" }

Checkbox to text field

Use when you want to store the label text of selected options.

{
  identifier: "dfe_selecteditems",
  type: "checkbox",
  friendlyName: "items",
  required: true,
  targetType: "text"
}

ConstructData output (single selection):

{ "dfe_selecteditems": "Sports" }

ConstructData output (multiple selections - returns array):

{ "dfe_selecteditems": ["Sports", "Music"] }

File input

Use for file upload fields, with either the plain file input or GOV.UK's improved file upload component. See the file upload component for the HTML.

{
  identifier: "dfe_document",
  type: "file",
  friendlyName: "a document",
  required: true,
  allowedFileTypes: ["pdf", "doc", "docx"],
  maxFileSize: 3,   // MB
  fileLimit: 3      // maximum number of files
}

ValidateData checks each file's extension, the number of files and each file's size, in that order, then sends the files to be virus scanned. Set all 3 properties on every file input:

  • allowedFileTypes: extensions in lowercase, without the dot
  • maxFileSize: the largest file, in megabytes
  • fileLimit: how many files can be selected at once

Virus scanning needs the VirusScan server logic on your site. See scanning uploaded files for viruses, including the largest files that can be scanned. If the input is optional and no file is selected, all the checks, including the scan, are skipped.

File inputs are validated but not included in ConstructData output. After the record is saved, use one of these to upload the file:

  • DfEPortal.WebApi.UploadFile - Use when uploading to a file column or image column directly on the entity record.
  • DfEPortal.WebApi.ProcessFileAndUploadToNotes - Use when uploading files as note attachments (annotations) linked to the record.

Both only upload the first file selected in the input.

In version 02 and earlier, the framework doesn't work with the improved file upload component: the virus scan passes without scanning and nothing is uploaded. Use the plain file input until your site is on version 03.

Available functions

Most functions are asynchronous: they return a promise, so call them with await inside an async function. Where a Web API call fails, the framework also adds a general error to the error summary for you.

Web API functions take the table's entity set name, which is usually its logical name in the plural, for example contacts or dfe_applications. Check it in the table's properties. The one exception is ProcessFileAndUploadToNotes, which takes the logical name.

DfEPortal.ValidateData(inputObjArr, errorContainer)

Error messages on the page are handled within this function. It doesn't stop your code when validation fails: check the value it resolves with.
Purpose
Validates every input, shows an error on each field that fails, and shows and focuses the error summary.
Parameters
  • inputObjArr: Array - the validation data object array (see above).
  • errorContainer: String or jQuery object (optional) - the error summary container. Defaults to #error-summary-container. See displaying custom errors.
Returns
A promise that resolves with true if every input passed, or false if any failed. It throws if the error container isn't on the page.
Example
const isValid = await DfEPortal.ValidateData(inputObj);
if (!isValid) {
  return;
}

DfEPortal.WebApi.ConstructData(inputsObj)

Purpose
Reads the value of each input from the page and builds the data object to send to CRM, using each input's type and targetType.
Parameters
inputsObj: Array - the validated input object array.
Returns
A promise that resolves with the data object. It rejects, and shows a general error, if an input's targetType is missing or not valid for its type.
Things to know
  • File inputs are left out of the data object.
  • If the data object would be empty, for example because the only input is a file, it waits for 30 seconds and then rejects. Don't call it with only file inputs.
  • Call ValidateData first. Lookup text inputs need the record ID it finds.

DfEPortal.WebApi.Create(entitySetName, dataObj)

Purpose
Creates a new record in the CRM.
Parameters
  • entitySetName: String - the table's entity set name (e.g. leads).
  • dataObj: Object - data object constructed by DfEPortal.WebApi.ConstructData.
Returns
A promise that resolves with the ID of the new record, or rejects with { status, statusText, responseText, error }.

DfEPortal.WebApi.Update(recordId, entitySetName, dataObj)

Purpose
Updates an existing record in the CRM. Only the columns in dataObj change.
Parameters
  • recordId: String - the ID of the record to update.
  • entitySetName: String - the table's entity set name (e.g. contacts).
  • dataObj: Object - data object constructed by DfEPortal.WebApi.ConstructData, or your own object of column names and values.
Returns
A promise that resolves when the record is updated, or rejects with { status, statusText, responseText, error }.

DfEPortal.WebApi.Retrieve(entitySetName, searchQuery)

Purpose
Retrieves records from a CRM table using an OData query.
Parameters
  • entitySetName: String - the table's entity set name (e.g. contacts).
  • searchQuery: String - the OData query, starting with ? (e.g. ?$select=firstname,lastname&$filter=emailaddress1 eq 'test@example.com'). It's added straight after the entity set name, so it can also be a record ID in brackets, such as (00000000-0000-0000-0000-000000000000)?$select=firstname.
Returns
A promise that resolves with the Web API's response. For a query, the records are in its value property.

DfEPortal.WebApi.Delete(recordId, entitySetName)

Purpose
Deletes a record from the CRM.
Parameters
  • recordId: String - the ID of the record to delete.
  • entitySetName: String - the table's entity set name.
Returns
A promise that resolves when the record is deleted, or rejects with an error.

DfEPortal.WebApi.Associate(recordId, entitySetName, relationshipName, dataObj)

Purpose
Links two records through a relationship, for example a many-to-many relationship behind a set of checkboxes.
Parameters
  • recordId: String - the ID of the record you're starting from.
  • entitySetName: String - its table's entity set name.
  • relationshipName: String - the relationship's navigation property name.
  • dataObj: Object - the record to link to, as an OData reference: { "@odata.id": "/dfe_regions(00000000-0000-0000-0000-000000000000)" }.
Returns
A promise that resolves when the records are linked, or rejects with an error.

DfEPortal.WebApi.Disassociate(recordId, entitySetName, relationshipName, relatedId)

Purpose
Removes the link between two records. Neither record is deleted.
Parameters
  • recordId, entitySetName, relationshipName: as for Associate.
  • relatedId: String - the ID of the linked record to remove.
Returns
A promise that resolves when the link is removed, or rejects with an error.

DfEPortal.WebApi.CallCloudFlow(flowApiId, data)

Purpose
Calls a Power Automate cloud flow and returns its response.
Parameters
  • flowApiId: String - the API ID of the cloud flow.
  • data: Object - the flow's input. It's sent as a JSON string in eventData.
Returns
A promise that resolves with the flow's response, parsed from JSON, or rejects with an error. Unlike the other Web API functions, it doesn't add an error to the summary for you.
When to use
For calls to another service, or work that needs a key or secret, consider server logic instead. It's quicker and runs as the signed-in user.

DfEPortal.WebApi.UploadFile(identifier, entitySetName, recordId)

Purpose
Uploads the selected file to a file or image column on a record.
Parameters
  • identifier: String - the file input's identifier, which is also the file column's logical name.
  • entitySetName: String - the table's entity set name (e.g. dfe_applications).
  • recordId: String - the ID of the record to upload the file to.
Returns
A promise that resolves with { input, resolve: true, fileName } when the file is uploaded, or rejects and shows a general error.
Things to know
  • If no file is selected, it does nothing and resolves with undefined, so you don't need to check first.
  • It only uploads the first selected file.
  • It works with both the plain file input and the improved file upload component.

DfEPortal.WebApi.ProcessFileAndUploadToNotes(identifier, logicalName, recordId)

Purpose
Uploads the selected file as a note (annotation) attachment linked to the record. The note's text is *WEB*.
Parameters
  • identifier: String - the file input's identifier.
  • logicalName: String - the table's logical name (e.g. dfe_application), not its entity set name.
  • recordId: String - the ID of the record to attach the note to.
Returns
A promise that resolves with { input, fileName }, or rejects with an error.
Things to know
  • If no file is selected, it rejects, so check first or only call it after validating a required file input.
  • It only uploads the first selected file.
  • It finds the table by adding "s" to the logical name, so it doesn't work for tables whose entity set name is different.

DfEPortal.WebApi.DeleteFile(columnName, recordId, entitySetName)

Purpose
Deletes the file in a file or image column, for example when the user removes or replaces a file.
Returns
A promise that resolves with the column name, or rejects with an error. Note the order of the parameters, which is different from UploadFile.

DfEPortal.GetFileContent(identifier, format)

Purpose
Reads every file selected in a file input, for example to send it to server logic.
Parameters
  • identifier: String - the file input's identifier.
  • format: String (optional) - "base64" (the default) or "binary" for an ArrayBuffer.
Returns
A promise that resolves with an array of { fileName, mimeType, fileSize, fileExtension, fileContent }, one for each file. If no file is selected, it shows an error on the field and rejects.

DfEPortal.Errors

Use these to show errors that don't come from ValidateData, for example after a failed Web API call. Displaying custom errors has examples.

Function What it does
ShowInputError(identifier, type, message) Adds an error message to a field, with the error styles, and links it with aria-describedby. Use the same type as in the validation data object.
ClearInputError(identifier, type) Removes a field's error message and styles.
ShowErrorSummary(container) Adds an empty error summary to the container, if there isn't one already.
AddErrorSummaryDetail(identifier, message, container) Adds a link to the error summary, creating the summary if needed. The link goes to #[identifier]-error, the field's error message. Pass an empty identifier for an error that isn't about a field.
RemoveErrorSummaryDetail(identifier, container) Removes a field's link from the error summary.
FocusErrorSummary(scrollOptions, container) Scrolls to the error summary and moves focus to it. scrollOptions is { offset, duration }: pass {} for the defaults. The container is the second parameter.
HideErrorSummary(container) Removes the error summary.

Lower-level validation helpers

ValidateData uses the functions in DfEPortal.ValidationHelper, such as IsEmail, IsTelephone, IsDateValid, FileSizeCheck and VirusCheck. You can call them yourself for a custom check. Each returns { identifier, value, errorMessage }, where value is true if the check passed, except VirusCheck and TextInputSearchValidation, which return a promise of the same thing.

Don't use DfEPortal._FileHelpers. It's internal to the framework and may change between versions.

Best practices

  • Always check the value ValidateData resolves with, and stop if it's false.
  • Use await with ValidateData, ConstructData and the Web API functions, inside an async function.
  • Use entity set names, such as contacts, with the Web API functions, except ProcessFileAndUploadToNotes.
  • Use try-catch blocks to handle errors, and re-enable the button and hide the spinner if something fails.
  • Use DisableButton and ShowLoadingSpinner during processing to prevent multiple submissions and provide visual feedback.
  • Ensure your inputObj properties (e.g. required, targetType) match the form's requirements to avoid unexpected behaviour.
  • Keep any check users mustn't be able to get around, and anything that needs a key, in server logic. Code in the browser can be changed by the user.
  • Avoid logging sensitive data (e.g. email addresses) to the console in production.
