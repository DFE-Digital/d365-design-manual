What the framework is

Sites built from the base portal load a shared set of files that DfE hosts centrally:

  • GOV.UK Frontend, in GOV.UK and DfE-branded versions, including its CSS and JavaScript
  • the DfE custom components' styles and JavaScript
  • the CRM helper framework, dfe-crm-portal-helper.js

Each release is published as a numbered version, such as v02 or v03. Your site chooses a version through its web file records, so a new release doesn't change your site until you move to it.

Versions

Version What it includes
v03 Support for GOV.UK's improved file upload component, virus scanning for larger files, and GOV.UK Frontend 6.6. See what changed in version 03.
v02 The content wrapper component. Virus scanning moved from a call in the browser to the VirusScan server logic.
v01 First release.

This manual describes the latest version. Where something works differently in an earlier version, the page says so.

Check which version your site uses

  1. Open the Portal Management app and go to Web Files.
  2. Open a framework file, such as dfe-crm-portal-helper.js.
  3. Look at its Cloud Blob Address. The version is the folder after the storage address, for example /v02/ in https://<storage account>.blob.core.windows.net/v02/scripts/dfe-crm-portal-helper.js.

All the framework's web files on a site should use the same version.

Move to a new version

  1. Read what's changed in the new version, and check your pages for anything it affects.
  2. In your development environment, change the Cloud Blob Address of each framework web file to the new version, for example from /v02/ to /v03/.
  3. Clear the site's cache, so it loads the new files.
  4. Test your site, in particular forms, validation, error messages and file uploads.
  5. Move your other environments in the same way, as part of your normal release.

To move back, change the addresses back to the version you were using.

For the storage address for your environments, email Eddie Haynes or Steve Tam in the Solutions Delivery Team.

What changed in version 03

Improved file upload component

The framework now works with GOV.UK's improved file upload component, which lets users drag and drop files, as well as with the plain file input. Pages using the plain input don't need to change.

In version 02 and earlier, the framework couldn't find the files in the improved component. Virus scans passed without scanning anything, uploads saved nothing and validation failed. Don't use the improved component on a site that's still on version 02.

See the file upload component for how to use it.

Larger files can be virus scanned

The framework now sends files to the VirusScan server logic as text, not as application/json. In version 02, Power Pages rejected files over about 750 KB before they were scanned.

The standard VirusScan server logic works with both. For files over about 2 MB, your site also needs the memory site setting, and the current server logic code. See scanning uploaded files for viruses.

GOV.UK Frontend 6.6

GOV.UK Frontend has been upgraded from 6.1 to 6.6. No existing HTML has to change. A few things look slightly different, such as the spacing in the header, and some markup is now recommended:

  • Improved file upload: use the govuk-file-upload-wrapper class, not govuk-drop-zone, which will be removed in GOV.UK Frontend 7.
  • Start buttons whose text contains HTML, such as visually hidden text: wrap the text in a <span>, or the spaces between words disappear. Keep the arrow outside the <span>. Start buttons with plain text don't need it.
<a href="/start" role="button" draggable="false" class="govuk-button govuk-button--start" data-module="govuk-button">
  <span>Start <span class="govuk-visually-hidden">your application</span> now</span>
  <svg class="govuk-button__start-icon" ...>...</svg>
</a>
! Warning Keep using data-maxwords for character counts with a word limit. GOV.UK Frontend 6.6 replaces it with data-maxlength and data-count-type="words", but the framework doesn't support that yet: it would treat the limit as characters and wouldn't check the number of words.

data-maxwords still works. GOV.UK Frontend shows a warning about it in the browser's console, which you can ignore. See the GOV.UK Frontend release notes (opens in a new tab) for everything else that changed.

What to check after moving

  • your pages' header, inputs with a prefix or suffix, and inline radios with long labels
  • start buttons with visually hidden text, or other HTML, in their text
  • file uploads, including error messages, the link from the error summary, drag and drop, and virus scanning
  • character counts, which should still count words or characters as before

If you would like any additional advice or guidance with moving to a new version, email Eddie Haynes or Steve Tam in the Solutions Delivery Team.
